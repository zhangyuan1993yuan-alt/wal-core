## 修复「浏览器能打开 GitHub、git 却不能提交」（同日追记，推翻上面「必然失败」的结论）
根因三层：
1. **路径不同**：Chrome 读注册表系统代理 `127.0.0.1:7897`；命令行 shell 被注入**动态端口的沙箱代理**（本轮 55380 → 60890），只放行白名单 → `api.github.com` 200、`github.com` CONNECT 502
2. **Clash Verge 的 mihomo 核心当时整体不可用**：走 7897 的 google.com(5s 超时)、baidu.com(30s 超时)、api.github.com(5s 超时)、github.com(TLS 握手 5s 无响应) 全失败；7898/7899/9097 均未监听。`config.yaml` 有 `- DOMAIN-KEYWORD,github,Proxy` 但节点不通。浏览器能打开靠残留 keep-alive 连接/缓存，不是代理链路健康
3. **认证缺失**：私有仓库需凭据，Windows 凭据管理器原本无 GitHub 条目 → git 报 `could not read Username`

修法（已完成并验证）：
- `git config --local http.proxy ""` + `https.proxy ""`：空值覆盖环境变量代理，强制直连（本轮直连 4/4 HTTP 200 ≈0.9s；曾出现 2/3 超时的短时抖动，属跨境链路波动，重试即可）
- `git credential approve` 把 github-pat 的 PAT 存入 Windows 凭据管理器（`protocol=https / host=github.com / username=x-access-token`），全程未回显、未落盘到仓库
- 验证：裸 `git ls-remote` / `git push`(Everything up-to-date) / `git fetch` 退出码全 0；真实写路径用临时分支 `__connectivity_check` 推送+删除成功，远端最终只剩 `refs/heads/main = f6a2e5d`
- 切换/撤销：代理修好而直连失效时 `git config --local http.proxy http://127.0.0.1:7897`；恢复默认 `git config --local --unset http.proxy`
- 全局可选（**未擅自设置**）：`git config --global 'http.https://github.com/.proxy' ''`，只对 github.com 生效
- 用户侧建议：重启 Clash Verge 或换节点，否则浏览器新建连接也会失败
